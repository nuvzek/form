# Internationalization

Read this reference whenever the user requests multiple languages, a locale switcher, translated labels/options/placeholders, or localized validation messages.

## Locale source

Use a project-owned reactive source when users can switch language:

```ts
const [Form, { locale: resolvedLocale }] = useForm({
  schemas,
  locale, // string, ref, computed, or getter
  localeMap: { "en-UK": "en-US" },
  fallbackLocale: "zh-CN",
});
```

A ref, computed, or getter is watched by each Runtime. Schema functions and dictionaries that read locale are reevaluated when it changes. The returned `locale` is a read-only computed containing the canonical value.

Global defaults may also be set in `defineFormSetup.default`: `locale`, `localeMap`, `fallbackLocale`, and `messages`. Instance options override global defaults. Object locale maps are merged; an instance function map takes precedence over a global function map.

Built-in locales are `zh-CN`, `en-US`, and `zh-HK`. Built-in aliases include `zh`, `zh-Hans`, `en`, `en-GB`, `yue`, `yue-Hant`, and `zh-Hant-HK`. A custom `localeMap` can be an object or `(raw: string) => string`.

## Local Schema

`label`, `placeholder`, and `required` accept string-valued dictionaries directly:

```ts
{
  component: Input,
  field: "name",
  label: { "zh-CN": "姓名", "en-US": "Name" },
  required: true,
}
```

Use `i18n()` for other properties or dictionary values that are objects:

```ts
import { i18n } from "@nuvzek/form";

componentProps: i18n({
  "zh-CN": { options: [{ label: "男", value: "male" }] },
  "en-US": { options: [{ label: "Male", value: "male" }] },
})
```

`i18n()` values may be strings, arrays, or complete configuration objects. Do not use it in pure JSON.

A dynamic function may read `utils.locale` when text needs computation:

```ts
label: ({ locale }: any) => locale === "en-US" ? "Name" : "姓名",
```

## SSR JSON

Use direct dictionaries for `label`, `placeholder`, and `required`. Use `I18N` for options and other dynamic values:

```json
{
  "$dispatch": "I18N",
  "values": {
    "zh-CN": [{ "label": "男", "value": "male" }],
    "en-US": [{ "label": "Male", "value": "male" }]
  }
}
```

The selected branch may contain another dispatch or dynamic value. The validator checks that `I18N.values` is an object.

## Built-in messages

Override or extend `messages` globally or per form:

```ts
messages: {
  "en-US": {
    "placeholder.input": "Please enter {label}",
    "placeholder.select": "Please select {label}",
    "rule.required": "{label} is required",
  },
}
```

Only these built-in templates are used by the core:

- `placeholder.input`
- `placeholder.select`
- `rule.required`

The `{label}` variable is replaced with the resolved label. Select-like placeholders are chosen when the resolved component name contains `select`, `tree`, or `cascader` case-insensitively. Set `schema.placeholder` explicitly when the component name cannot be inferred reliably.

## Fallback behavior

Built-in messages resolve in this order: current locale, `fallbackLocale`, then `zh-CN`. Schema dictionaries resolve in this order: current locale, `fallbackLocale`, then the dictionary's first value.

Keep the same canonical locale keys in dictionaries after applying `localeMap`. Do not normalize each dictionary separately.

## Verification

For a language-switching form, exercise at least two locales and switch back once. Check labels, explicit and generated placeholders, required messages, options, and dynamic locale functions. Wait for reactive updates before asserting. For SSR, also run the JSON validator.

See `assets/local-i18n.tsx` and `assets/ssr-i18n.json` for complete examples.
